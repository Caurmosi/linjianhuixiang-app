# 第一部分 · 需求正文（与已复制给 AI 的版本一致）

**任务：为《林间回响》城市鸟类宜居度诊断 App 开发后端服务。**

**项目背景**：这是一个通过 BirdNET 识别鸟声、耦合人为噪声评估"城市绿地鸟类宜居度"的 App。前端已完成（React 18 + Vite 的移动端 H5，另有 Android WebView 壳），代码在 GitHub：`https://github.com/Caurmosi/linjianhuixiang-app`。前端已预留好数据访问层，后端只需要实现接口，前端通过环境变量 `VITE_USE_MOCK=false` 即可一键切换到真实数据，UI 无需任何改动。

**核心能力要求**（按优先级）：
1. **音频分析管线**：接收前端上传的音频（wav/mp3/webm）→ 预处理（重采样 48kHz/16bit、去噪）→ **BirdNET 模型识别鸟种**（返回物种名+置信度）→ 计算**声学指数**（ACI 声学复杂度、NDSI 归一化声景、ADI 声学多样性、H 均匀度）→ 估算**人为噪声占比** → 综合计算**宜居度评分**（0-100）和等级（≥70 宜居 / ≥50 一般 / <50 受压）
2. **历史记录**：保存每次分析（录音文件名、物种数、得分、噪声占比、时间），支持列表查询
3. **健康检查**：`GET /health` 返回服务状态

**必须匹配的接口契约**（前端 `apiService.js` 已定义 12 个函数，后端需提供对应 REST 接口，返回字段与前端 `mockData.js` 完全一致）：
- `GET /api/species` → 物种清单数组 `[{id, name, latin, conf, freq, period}]`
- `GET /api/indices` → `[{key: 'ACI'|'NDSI'|'ADI'|'H', name, display, pct, desc}]`
- `GET /api/livability` → `{score, grade, gradeEn, bio, sound, noise}`
- `GET /api/heatmap` → 4×12 二维数组（0-1 强度）
- `GET /api/map-points` → `[{x, y, c, t}]`（空间样点）
- `GET /api/green-spaces` → `[{name, points: [...]}]`（多绿地）
- `GET /api/suggestions` → 字符串数组
- `GET /api/history` → `[{id, name, species, score, duration, noise, bio, sound}]`
- `POST /api/analyze`（multipart 上传音频）→ 返回完整分析结果：`{recording, species[], indices[], livability{}, heatmap[][], mapPoints[], suggestions[], speciesCount}`

**技术选型建议**：Python + FastAPI（BirdNET 生态好，推荐）或 Node.js + Express；音频处理用 librosa/ffmpeg；BirdNET 用官方预训练模型（TFLite 或 PyTorch）；数据库用 SQLite 起步（后续可换 PostgreSQL）。**部署**：提供 Dockerfile，能在云端容器部署。

**验收标准**：① 用一段真实鸟鸣音频调用 `/api/analyze` 能返回合理的物种+指数+宜居度；② 接口返回字段与上述契约一致（可跑前端 `tests/dataContract.test.js` 验证）；③ 有 `/health` 端点；④ README 写清本地启动步骤和 Docker 部署方式。

**请先读**：`frontend/src/data/mockData.js`（数据结构基准）和 `frontend/src/services/apiService.js`（接口清单），再动手。

# 第二部分 · 补充实现细节（可选，用于指导 AI 落地）

> 以下内容是对第一部分的细化，不影响契约，AI 可按需参考。若已按第一部分开工，可忽略。

## 2.1 架构说明（关键决策）

**识别用「免费多模态 AI API」，其余模块自研（确定性算法）**：

```
前端 App ──上传音频──> 后端服务 ──调多模态 API──> 多模态 AI（鸟声识别）
                          │                            │
                          │ <──识别结果（鸟种+置信度）──┘
                          │
                          ├── 音频预处理（ffmpeg：16kHz/单声道/去噪）
                          ├── 声学指数（自研：ACI/NDSI/ADI/H，librosa）
                          ├── 宜居度评估（规则模型：多样性+声环境加权）
                          └── 历史存储（SQLite 起步）
```

> ⚠️ 与原需求的关系：原需求写"BirdNET 模型识别鸟种"；本方案将识别实现为**调免费多模态 API（如智谱 GLM-4V-Flash / qwen-audio / Gemini 免费层）**，仅替换"识别"这一环的实现方式，接口契约不变。若 API 不可用，可回退本地 BirdNET 或 mock。**请把识别封装成独立模块（如 `recognizer.py`），隔离实现，便于替换。**

## 2.2 自研模块要点

| 模块 | 实现方式 |
|---|---|
| 音频预处理 | ffmpeg 转 16kHz/单声道/16bit + 静音截断 |
| 声学指数 | librosa：ACI=频谱时间梯度绝对值和；NDSI=中/低频段能量比；ADI=频带分布多样性；H=归一化熵 |
| 噪声占比 | 低频段（<2kHz）能量占比，结合 NDSI 交叉验证 |
| 宜居度评分 | `score = bio×0.5 + sound×0.5`；bio=物种数归一化，sound=噪声+NDSI 加权；等级：≥70 宜居 / ≥50 一般 / <50 受压 |
| 多模态识别 | 封装 `recognizer.py`：截取 10-30s 有效片段 → 调免费多模态 API → 映射 `[{species_name, confidence}]`；**必须处理** API Key 失效/超时/无结果 → 优雅降级不崩溃 |
| 历史存储 | SQLite 表 `analyses(id, recording, species, score, duration, noise, bio, sound, created_at)` |

## 2.4 实施顺序（每阶段可独立验收）

1. **骨架**：FastAPI 结构 + `/health` + 所有 GET 接口返回 mock 契约数据
2. **指数**：音频预处理 + 声学指数（librosa）+ 单测
3. **识别**：多模态 API 识别模块 + 降级逻辑
4. **评分**：噪声估算 + 宜居度规则 + `/api/analyze` 完整串联
5. **存储**：SQLite 历史 + `/api/history`
6. **部署**：Docker + README
